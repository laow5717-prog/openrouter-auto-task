# 充值报表与账号金额视图

## Goal

后台目前只有**流水明细**（`RechargeLogs.vue` 逐条列 recharge_logs），没有任何聚合视图：
想知道「今天充了多少钱」「这个月消耗了多少张卡」「哪个账号已经充满了」，只能自己翻页数。
账号列表 (`/api/accounts`) 也不返回金额，判断一个账号该不该继续充、该不该核销，
必须点开「充值记录」逐条加。

本任务补上两块：

1. **新增独立「报表」页**：按日的充值金额 / 笔数 / 使用卡片数 / 账号数，加区间汇总与账号维度榜单。
2. **账号列表加金额列**：今日充值金额、累计充值金额，并把「已归档（已核销）」与在用账号在汇总里分开算。

## 口径（全局约定，所有新增统计一律遵守）

- **金额只算 `status='success'`**。失败/pending 的记录不计入任何金额，只在「笔数 / 成功率」指标里出现。
- **按当前选中平台过滤**（`platform` 列）。前端 `api/index.js` 的 `get()` 已统一注入 `currentPlatform`，
  新接口直接用 `_req_platform()` 读取即可。跨平台合计不做——两个平台的账号体系与卡池是隔离的，
  合在一起的数字没有可操作性。
- **日期按 `DATE(created_at)`**，`created_at` 已是 `datetime('now','localtime')` 写入的本地时间字符串，
  「今日」判据统一写 `DATE(created_at)=DATE('now','localtime')`，与 `has_today_record` /
  `count_success_by_last4` 现有写法保持一致。
- **卡片数按去空格后的完整 `card_display` 去重**。不按末 4 位聚合——那是 `count_success_by_last4`
  为兼容历史脱敏串做的妥协，用在「用了多少张卡」上会把不同卡号的同末 4 位合并成一张，数字偏小。
- **「已核销」= `accounts.identity_status='retired'`**。这是既有的归档终态（见 `/api/accounts/archive`），
  UI 上「已归档」与「已核销」是同一件事的两个叫法，本任务统一显示为「已核销（已归档）」。

## Requirements

### R1 — 报表接口 `GET /api/reports/recharge`

入参：`platform`（自动注入）、`date_from`、`date_to`（均为 `YYYY-MM-DD`，可缺省）。
缺省区间为**最近 30 天**（含今天）。返回三段数据：

- **`summary`**：区间内 总金额 / 成功笔数 / 失败笔数 / 成功率 / 去重卡片数 / 去重账号数，
  外加**不受区间影响的今日四项**（今日金额、今日成功笔数、今日卡片数、今日账号数）——
  KPI 卡要显示「今天」，不能因为用户把区间拉到上个月就变成 0。
- **`daily`**：区间内逐日一行（日期 / 金额 / 成功笔数 / 失败笔数 / 卡片数 / 账号数），日期倒序。
  **只返回有记录的日期**，无记录的日子不补零行（补零由前端画图时决定，接口不造数据）。
- **`accounts`**：账号维度聚合（邮箱 / 金额 / 成功笔数 / 卡片数 / 最后充值时间 / `identity_status`），
  按金额倒序，最多 100 行。带 `identity_status` 是为了在榜单里标出哪些已核销。

同时返回 `verified`（已核销账号的金额与账号数）与 `active`（其余账号的），供概览区分开展示。

### R2 — 账号列表返回金额

`GET /api/accounts` 每行新增两个字段：

- `recharge_today`：该账号在**当前平台**今日成功充值金额；
- `recharge_total`：该账号在当前平台的累计成功充值金额。

无记录返回 `0`（不是 `null`）——列表要能直接排序/求和，null 会在前端到处加判空。

实现上必须是**一次聚合查询**（按本页 emails 批量 IN），不得逐账号查询。参照
`success_amount_by_email` / `count_by_emails` 的既有做法：账号页默认 20 行、可调到 100，
N+1 会让每次翻页打上百条 SQL。

### R3 — 报表页 `/reports`

新增路由与侧边栏入口（`Icon name="wallet"` 已被充值记录占用，用 `dashboard` 或 `history`），
页面自上而下：

1. **今日 KPI 区**：今日充值金额 / 今日成功笔数 / 今日使用卡片数 / 今日充值账号数，
   复用既有 `.stats-grid` + `.stat-card` 样式。
2. **区间筛选**：起止日期 + 查询 / 重置，复用 `FilterBar`。默认最近 30 天。
3. **区间汇总**：总金额、成功/失败笔数与成功率、去重卡片数、去重账号数；
   并列显示「已核销账号贡献 $X（N 个）」与「在用账号 $Y（M 个）」。
4. **每日趋势**：表格 + 行内纯 CSS 柱状条（条长 = 当日金额 / 区间最大日金额）。
   **不引入任何图表库**——前端当前依赖只有 vue / vue-router / pinia，为一张柱状图加运行时依赖不划算。
5. **账号榜单**：R1 的 `accounts` 段，带「已核销」标签，行内可跳转到该账号的充值记录。

### R4 — 账号列表金额列与核销汇总

- 表格新增两列：「今日充值」「累计充值」，`$0.00` 格式，0 显示为灰色 `-` 以免视觉噪音。
- 表格上方（`FilterBar` 下）加一条汇总带：**当前页**的今日合计 / 累计合计，
  并拆成「已核销」与「在用」两组。
  - 明确只统计**当前页**，且 UI 文案要写明「当前页合计」。跨页合计需要另一次全量聚合查询，
    在有 `platform_status` 前端过滤导致分页与 total 对不齐的情况下（见 `/api/accounts` 注释）
    很容易给出自相矛盾的数字。
- 身份状态筛选已有 `retired` 选项（显示「已归档（停用）」），文案改为「已核销（已归档）」，
  与报表页术语统一。

## 验收标准

1. `/reports` 页在两个平台间切换时数字随之变化；把日期区间设为未来某天，`daily` 为空但今日 KPI 仍正确。
2. 报表 `summary.total_amount` 与同区间同平台 `recharge_logs` 中 `status='success'` 的 `SUM(amount)` 一致。
3. 账号列表某账号的 `recharge_total`，等于点开其「充值记录」后成功记录金额之和（当前平台部分）。
4. 已归档（retired）账号在报表账号榜单中带「已核销」标签，且其金额计入 `verified` 而非 `active`。
5. 账号页翻页时 SQL 条数不随 page_size 线性增长（金额来自单条聚合查询）。
6. `npm run build` 通过，无新增前端依赖。

## 范围外（明确不做）

- **不改 `GET /api/recharge-logs` 的既有行为**。它当前**忽略** platform 参数，返回跨平台流水。
  这与本任务的口径不一致，但改它会静默改变用户已经在看的那个页面的数据，属于独立决策，
  应单独提任务。报表页自有 platform 过滤，不受影响。
- 不做导出（Excel/CSV）。现有 `/api/accounts/export`、`/api/card/history/export` 是另一套模版逻辑，
  报表导出等页面稳定后再提。
- 不做账号列表的跨页金额合计与按金额排序（需要把聚合并进分页 SQL，与现有 `platform_status`
  前端过滤冲突，见 R4 说明）。
- 不改 `recharge_logs` 表结构，不加索引。当前数据量下 `GROUP BY DATE(created_at)` 全表扫可接受；
  真的慢了再单独提索引任务。
