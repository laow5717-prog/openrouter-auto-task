# 多平台并发运行

## Goal

让 opencode.ai 与 infron.ai **两个平台同时跑**，各自占用一部分 AdsPower 环境，
互不阻塞。目前后端 `AppState` 是单例、`platform` 与 `is_running` 都是它上面的单个
字段，第二个任务会被 `is_running` 直接挡掉（400「有任务正在运行」）。

## Background

多平台架构任务（08-03，已归档）当初**明确选择了不做并发**——一次只跑一个平台。
抽象层（`PlatformAdapter` 协议、`platform_accounts`、`card_platform_state`）就是按
这个前提设计的：数据层已经完全按平台隔离，**卡池、账号状态、记账都不需要再动**。

真正的阻塞点只在运行时状态：`AppState` 把「当前跑哪个平台」和「跑没跑」当成了全局
单例属性，所有流水线入口都是先 `state.platform = platform` 再起线程。两个平台同时跑
会互相覆盖这个字段，第二个任务一启动，第一个任务正在跑的选卡、记账就全串到另一个
平台去了。

数据层不用动这一点是本任务能成立的前提——它把改动面限制在运行时状态与 UI。

## Requirements

### 运行上下文按平台隔离

把 `AppState` 上属于「单次运行」的状态（`is_running` / `stop_requested` /
`platform` / `success_count` / `fail_count` / `current_action` / 日志缓冲 / 截图帧）
从全局属性降级为**按平台键控的运行上下文**。跨平台共享的部分（DB、models、配置、
`PaymentCardRegistry`）保持单例。

`/api/status`、`/api/stop` 这类端点要能按平台寻址；不带平台参数时的行为要明确定义
（建议：返回全部平台的状态汇总，而不是猜一个）。

### AdsPower 环境配额：软上限可借用

- opencode 上限 7 个环境，infron 上限 4 个，**总数不超过 11**
  （AdsPower 硬配额 12，减去它自带的 Default Profile）
- 对方空闲时可临时借用其额度，但总数仍受 11 约束
- 借出的额度在原主需要时要能收回（归还/抢占策略需在 design 里定死，
  这是三个配额方案里唯一需要处理抢占的，也是本任务最容易写出竞态的地方）

### 卡占用：全局互斥

同一张卡在任一时刻只能被一个平台**使用中**。`PaymentCardRegistry._in_flight` 现在
就是按裸卡号全局去重的，这个语义**必须保留**——同一张卡在几秒内被两个商户同时请求
授权是典型的盗刷特征，会直接触发发卡行风控。

注意与数据层的区别：卡的**状态**（判废/冷却/已付）按平台隔离，卡的**并发占用**全局
互斥。两者不矛盾，别在实现时混为一谈。

### UI：保留切换器，各平台独立状态

- 顶部平台下拉框保留「当前查看哪个平台」的语义，但**不再因运行中被禁用**
- 日志、进度、计数、截图按所选平台显示
- 未被查看的那个平台在跑时，要有可见的提示（否则它出问题时用户看不见）

## Out of Scope

- 三个及以上平台同时跑（架构上应自然支持，但不作为本任务的验收目标）
- 数据层改动——`platform_accounts` / `card_platform_state` / 各 model 的平台隔离
  已经做完并在生产验证过，本任务不应触碰
- 新平台接入
- 单平台内部的并发度调整（每个平台内部跑几个账号是既有 `WorkerPool` 的事）

## Acceptance Criteria

### 运行时隔离

- [ ] AC1 两个平台的流水线可同时处于运行中，互不阻塞（不再返回「有任务正在运行」）
- [ ] AC2 停止一个平台不影响另一个平台继续跑
- [ ] AC3 一个平台的运行状态（计数、当前动作、日志）不会串到另一个平台
- [ ] AC4 一个平台崩溃/异常退出，另一个平台不受影响且状态正确收敛

### 配额

- [ ] AC5 两平台同时跑时，AdsPower 环境总占用**任何时刻都不超过 11**
- [ ] AC6 opencode 默认不超过 7、infron 不超过 4
- [ ] AC7 对方空闲时可借用其额度；原主需要时能拿回（具体策略见 design）
- [ ] AC8 配额耗尽时是**等待**而不是报错崩溃

### 卡

- [ ] AC9 同一张卡不会在两个平台同时处于使用中（`_in_flight` 全局互斥有效）
- [ ] AC10 卡的判废/冷却/已付状态仍按平台隔离，与并发无关

### UI

- [ ] AC11 平台切换器在任务运行中不再被禁用
- [ ] AC12 切换平台后，日志/进度/计数显示的是该平台的
- [ ] AC13 另一个平台正在运行时，界面上有可见提示

### 回归

- [ ] AC14 单平台单独运行的行为与改造前一致（opencode 流程不能被改坏）
- [ ] AC15 测试套件全绿（当前基线 304 passed），并新增并发与配额的测试

## Notes

- `AppState` 是流水线、充值、订阅、日志、截图都在用的共享状态，改坏了会影响
  已经跑通的 opencode 流程。AC14 是本任务的安全底线。
- 日志劫持（`_patch_prints`）是全局替换 print 的机制，两个平台同时跑时**日志串台是
  最可能出的问题**，design 阶段要重点解决。
- 两个平台同时跑会同时抢 AdsPower 环境与代理 IP，风控暴露面高于串行。
  这是用户明确要的，但值得在 design 里记一笔权衡。
